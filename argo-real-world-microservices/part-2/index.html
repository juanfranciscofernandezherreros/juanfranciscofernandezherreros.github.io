Argo Real World Microservices — Part 2 of the series

The Config Repo: gitops-config

Part 1 built the microservice and said "the manifests live in a separate repo." This part is that repo: what's actually inside it, why it's shaped the way it is, and how to add a second service without guessing.

00

Where this fits

Two repos, two jobs — Part 1, section 02 covers this in full. Short version: hello-world-argocd is code, Java, Docker. gitops-config is the "recipe book" — what should exist in the cluster, and it's the only repo ArgoCD's Application ever points at.

01

Two folders, two jobs

Everything in this repo is one of these two things.

applications/
One YAML file per microservice — the Application resource that tells Argo "watch this folder, deploy it here." Applied once with kubectl apply; after that Argo re-reads it from the live cluster, not from this repo.
manifests/<service>/
The actual Kubernetes objects for that service — Namespace, Deployment, Service. This is what the Application points at, and what Argo keeps in sync forever, every time it changes.
02

applications/hello-world.yaml, line by line

The whole file — 21 lines, nothing hidden.

apiVersion: argoproj.io/v1alpha1
kind: Application
metadata:
  name: hello-world
  namespace: argocd
spec:
  project: default
  source:
    repoURL: https://github.com/juanfranciscofernandezherreros/gitops-config.git
    targetRevision: HEAD
    path: manifests/hello-world
  destination:
    server: https://kubernetes.default.svc
    namespace: hello-world
  syncPolicy:
    automated:
      prune: true
      selfHeal: true
    syncOptions:
      - CreateNamespace=true
metadata.namespace
argocd — this object itself lives where Argo lives, not where the app runs. That's a different namespace, three lines down.
source.repoURL + path
This repo, folder manifests/hello-world — the two folders from section 01, pointing at each other.
destination.namespace
hello-world — where the app's pods actually run. Created automatically because of CreateNamespace=true below.
syncPolicy.automated
prune and selfHeal — explained in full in Part 1, section 03. Without this block, syncing would need a manual argocd app sync every time.
03

manifests/hello-world/

Three plain Kubernetes files — nothing Argo-specific in any of them. They'd work the same with a bare kubectl apply -f.

namespace.yaml

Namespace

One object, one line that matters: name: hello-world. Everything else in this folder lives inside it.

service.yaml

Service

ClusterIP on port 8080 — the stable address other things inside the cluster use to reach the app, regardless of which pod is currently running.

deployment.yaml

Deployment

The one worth reading closely: image: hello-world:local with imagePullPolicy: Never — there's no registry in this base (see Part 1, section 08), so the image has to already be sitting on the node via kind load, and Kubernetes must never try to pull it. It also carries the readinessProbe/livenessProbe hitting /actuator/health/* — the thing that makes the ArgoCD UI show Healthy instead of just Synced.

04

Adding a second service

No new concepts — just repeat the pattern with a new name.

1 You Copy manifests/hello-world/ to manifests/<new-service>/ and change every hello-world string to the new name — namespace, labels, image, service name.
2 You Copy applications/hello-world.yaml to applications/<new-service>.yaml. Change three fields: metadata.name, source.path, destination.namespace.
3 You git add . && git commit && git push.
4 You Register it: kubectl apply -f applications/<new-service>.yaml.
5 ArgoCD Picks it up, creates the namespace, deploys it — same reconciliation loop as hello-world, running as a second, completely independent Application.

Past 2-3 services, copy-pasting a whole file per service gets old — that's what an ApplicationSet is for (generates one Application per folder automatically). Not needed yet at n=1.

05

Reference commands

Register a service

kubectl apply -f applications/hello-world.yaml

See what Argo thinks is true right now

kubectl get application hello-world -n argocd
kubectl get application hello-world -n argocd -o jsonpath='{.status.sync.status} {.status.health.status}'

Force a re-read instead of waiting ~3 min

kubectl -n argocd annotate application hello-world argocd.argoproj.io/refresh=hard --overwrite
