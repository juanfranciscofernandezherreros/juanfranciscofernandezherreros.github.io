Part 0

powershell

2

Install Maven manually

Invoke-WebRequest -Uri "https://dlcdn.apache.org/maven/maven-3/3.9.16/binaries/apache-maven-3.9.16-bin.zip" -OutFile "$env:TEMP\apache-maven-3.9.16-bin.zip"
Get-FileHash "$env:TEMP\apache-maven-3.9.16-bin.zip" -Algorithm SHA512
Expand-Archive -Path "$env:TEMP\apache-maven-3.9.16-bin.zip" -DestinationPath "$env:LOCALAPPDATA\Programs" -Force
[Environment]::SetEnvironmentVariable("MAVEN_HOME", "$env:LOCALAPPDATA\Programs\apache-maven-3.9.16", "User")
[Environment]::SetEnvironmentVariable("Path", [Environment]::GetEnvironmentVariable("Path","User") + ";$env:LOCALAPPDATA\Programs\apache-maven-3.9.16\bin", "User")

Apache Maven has no winget package — winget install Apache.Maven fails with "No package found matching input criteria". Download the official binary, verify its checksum, unzip it, and put it on the user PATH instead.

Part 0

Test-NetConnection localhost -Port 8082

Returns False before the tunnel, True while kubectl is forwarding, and False again after Ctrl+C.

kubectl

15

Check the install

kubectl version --client

Part 0

Install ArgoCD itself into the cluster

kubectl create namespace argocd
kubectl apply -n argocd --server-side --force-conflicts \
  -f https://raw.githubusercontent.com/argoproj/argo-cd/stable/manifests/install.yaml
kubectl -n argocd rollout status deploy/argocd-server

--server-side matters here: a plain apply fails because the ApplicationSet CRD is bigger than the 262144-byte limit on the annotation a normal apply writes.

Part 1

Read the initial admin password

kubectl -n argocd get secret argocd-initial-admin-secret -o jsonpath="{.data.password}" | base64 -d

Needed once, to log into the ArgoCD web UI as admin the first time.

Part 1

Open the two local doors (ArgoCD UI + the app)

kubectl -n argocd port-forward svc/argocd-server 8081:443 &
kubectl -n hello-world port-forward svc/hello-world 8080:8080 &

Both run in the background (&) — the ArgoCD UI on 8081, the app itself on 8080. Doesn't survive a machine restart; re-run after one.

Part 1

Register a service with Argo

kubectl apply -f applications/hello-world.yaml

Creates the Application resource that tells Argo what to watch and where to put it. The only manual kubectl apply in the whole workflow — everything after this is Argo syncing on its own.

Part 1 Part 2

Check the pods came up, then reach the service

kubectl -n hello-world get pods
kubectl -n hello-world port-forward svc/hello-world 8080:8080

Same two-step check works for any namespace — swap in the generated service's own namespace and port.

Part 1 Part 3

Ask Argo what it thinks is true right now

kubectl get application hello-world -n argocd
kubectl get application hello-world -n argocd -o jsonpath='{.status.sync.status} {.status.health.status}'

Reads Argo's own record of an Application instead of the workload it manages — the second form prints just the sync/health status, handy for scripting.

Part 2 Part 4

Force Argo to re-read Git now

kubectl -n argocd annotate application hello-world argocd.argoproj.io/refresh=hard --overwrite

Skips the ~3 minute automatic polling interval — same effect as clicking "Refresh" in the UI, from the terminal.

Part 2

Register + verify a generated service

kubectl apply -f applications/godbyemicroservices.yaml
kubectl -n godbyemicroservices get pods
kubectl -n godbyemicroservices port-forward svc/godbyemicroservices 8082:8080

The same onboarding pattern from Part 1, applied to a second, independently generated service.

Part 3

Inspect the previous container termination

kubectl get pod -n godbyemicroservices -l app=godbyemicroservices \
  -o jsonpath="{.items[0].status.containerStatuses[0].lastState.terminated.reason} {.items[0].status.containerStatuses[0].lastState.terminated.exitCode}{'\n'}"

Distinguishes a kernel-level OOMKilled / 137 from a Java exception or a probe-driven restart.

Part 4

Wait for the repaired Deployment

kubectl rollout status deployment/godbyemicroservices -n godbyemicroservices

Waits until the repaired Deployment has its requested replica available, or returns a failure when the rollout deadline is reached.

Part 4

Open the complete OOM lab locally

kubectl port-forward -n argocd svc/argocd-server 8081:443
kubectl port-forward -n godbyemicroservices-postgres-oom svc/godbyemicroservices-postgres-oom 8082:8080
kubectl port-forward -n godbyemicroservices-postgres-oom svc/postgresql 5433:5432

Run each foreground tunnel in a separate terminal. They expose Argo CD, Spring Boot, and PostgreSQL only on the local workstation.

Part 5

Check the active cluster and OOM lab backends

kubectl config current-context
kubectl get svc,endpoints -n godbyemicroservices-postgres-oom
kubectl get pods -n godbyemicroservices-postgres-oom -o wide

Confirms that kubectl targets the intended kind cluster and that each Service has a pod endpoint before opening a local tunnel.

Part 5

Create and verify the PostgreSQL fixture

kubectl exec -i -n godbyemicroservices-postgres-oom postgresql-0 -- \
  psql -U goodbye -d goodbye -v ON_ERROR_STOP=1 -c \
  "CREATE TABLE IF NOT EXISTS goodbye_record (id BIGINT PRIMARY KEY, payload VARCHAR(64) NOT NULL); INSERT INTO goodbye_record (id, payload) SELECT value, 'goodbye-' || value FROM generate_series(1, 100000) AS value ON CONFLICT (id) DO NOTHING;"

kubectl exec -n godbyemicroservices-postgres-oom postgresql-0 -- \
  psql -U goodbye -d goodbye -c \
  "SELECT COUNT(*), MIN(id), MAX(id) FROM goodbye_record;"

Generates the fixture inside PostgreSQL and verifies its count and ID boundaries without transferring the table to the client.

Part 6

Inspect and repeat the non-restarting OOM

kubectl apply -f application-postgres-oom.yaml
kubectl wait --for=condition=Ready pod/postgresql-0 -n godbyemicroservices-postgres-oom --timeout=180s
kubectl get configmap,statefulset,pvc,svc,pod -n godbyemicroservices-postgres-oom
kubectl get application godbyemicroservices-postgres-oom -n argocd
kubectl get pod -n godbyemicroservices-postgres-oom
kubectl logs -n godbyemicroservices-postgres-oom godbyemicroservices-postgres-oom
kubectl delete pod -n godbyemicroservices-postgres-oom godbyemicroservices-postgres-oom
kubectl wait --for=condition=Ready pod/godbyemicroservices-postgres-oom -n godbyemicroservices-postgres-oom --timeout=180s

Confirms Synced / Degraded, preserves the failed pod at zero restarts, and deletes it only when the controlled drill must be repeated.
