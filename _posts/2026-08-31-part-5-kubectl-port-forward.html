00

The networking problem

A Kubernetes ClusterIP Service has an address that is routable only inside the cluster. The browser, PowerShell, DBeaver, and other programs on the Windows host cannot connect to it directly. Creating a LoadBalancer or an Ingress merely for a local diagnostic session adds infrastructure and expands exposure unnecessarily.

kubectl port-forward solves that narrow problem. It opens a TCP listener on the local computer and carries each connection through the already authenticated Kubernetes API connection. It is temporary: it neither changes the Service manifest nor commits anything to Git.

1 · Client

curl, browser, or DBeaver connects to localhost.

2 · kubectl

The foreground process accepts the local TCP connection.

3 · API server

The tunnel uses the active kubeconfig identity and context.

4 · Pod

Traffic reaches a pod selected behind the named Service.

The form is LOCAL_PORT:REMOTE_PORT. In 8082:8080, clients use port 8082 on the workstation while the application still listens on port 8080 in the pod.

01

Check the target first

Confirm the current cluster, the Services, and their endpoints before opening a tunnel. A Service without endpoints can accept the port-forward command but has no ready backend to receive the request.

kubectl config current-context
# kind-hello-world

kubectl get svc,endpoints -n godbyemicroservices-postgres-oom
kubectl get pods -n godbyemicroservices-postgres-oom -o wide

The lab exposes the Spring Boot Service on port 8080 and PostgreSQL on 5432. Argo CD lives in the separate argocd namespace and exposes HTTPS on Service port 443.

02

Open the three tunnels

Run each long-lived command in its own PowerShell window. The line Forwarding from 127.0.0.1... means the listener is ready; it does not mean that the command has finished.

# Argo CD web interface: https://localhost:8081
kubectl port-forward -n argocd svc/argocd-server 8081:443

# Goodbye HTTP API: http://localhost:8082
kubectl port-forward -n godbyemicroservices-postgres-oom svc/godbyemicroservices-postgres-oom 8082:8080

# PostgreSQL for DBeaver: localhost:5433
kubectl port-forward -n godbyemicroservices-postgres-oom svc/postgresql 5433:5432

Keep that terminal open. Pressing Ctrl+C, closing the window, suspending the machine, or losing the cluster connection destroys the tunnel. The later error curl: (7) Failed to connect is expected when the foreground process is no longer running.

03

Call the service correctly

Leave the port-forward running and use a second PowerShell window for the client. Pass a literal URL to curl.exe; Markdown link syntax such as [http://...](http://...) is documentation markup, not a valid command-line URL.

curl.exe -v http://localhost:8082/godbyemicroservices

In this failure lab, the endpoint deliberately reads the entire PostgreSQL result into an ArrayList. The expected call can therefore terminate the JVM with java.lang.OutOfMemoryError: Java heap space. After that, the standalone pod is Failed, does not restart, and the Service no longer has a usable backend. A subsequent curl failure is part of the experiment, not a port-forward defect.

kubectl get pod -n godbyemicroservices-postgres-oom
kubectl get application godbyemicroservices-postgres-oom -n argocd
kubectl logs -n godbyemicroservices-postgres-oom godbyemicroservices-postgres-oom

SELECT COUNT(*) AS total FROM goodbye_record;

Use SELECT COUNT(*) for validation. Asking DBeaver to render every row wastes client memory and does not test the service's JVM behavior.

05

Troubleshooting checklist

Connection refused

The port-forward process ended or never reached the “Forwarding” line. Start it again and keep it open.

Address already in use

Another process owns the local port. Choose another local number, for example 8083:8080.

No endpoints

Inspect the Service selector, pod labels, readiness, and target port.

Tunnel drops after OOM

The selected backend died. Inspect pod and Argo health before recreating the workload.

# Alternative local port; the remote application port remains 8080
kubectl port-forward -n godbyemicroservices-postgres-oom svc/godbyemicroservices-postgres-oom 8083:8080
curl.exe http://localhost:8083/godbyemicroservices

By default, kubectl binds to loopback, so only the local machine can use the tunnel. Keep that default for credentials and databases. Port-forwarding is a development and incident-diagnosis mechanism, not a production exposure strategy.
