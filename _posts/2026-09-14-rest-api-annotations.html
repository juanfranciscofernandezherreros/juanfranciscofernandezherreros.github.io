Spring Boot REST API annotations

A REST controller can accumulate an unsettling number of @Something annotations. The useful way to learn them is not memorization: it is understanding which part of the HTTP contract each annotation controls, which framework interprets it, and when you should avoid it.

01

What “all” means in a REST API

Java has no universal list of “REST annotations”. An API may combine annotations from Spring MVC, Jakarta Validation, Spring Security, Jackson, OpenAPI, JPA, Lombok, and project-specific libraries. Enumerating the entire ecosystem would produce a huge list with little practical value.

This guide covers the annotations you are likely to encounter at the HTTP boundary of a Spring Boot REST API: annotations that define endpoints, read requests, build responses, validate data, translate failures, control CORS and authorization, serialize JSON, or document the contract.

Mental model: whenever you see an annotation, first ask “who interprets it?”. @GetMapping belongs to Spring MVC; @NotBlank to Jakarta Validation; @JsonIgnore to Jackson; @PreAuthorize to Spring Security; @Operation to OpenAPI/Swagger.

02

@Controller, @ResponseBody and @RestController

@Controller

Declares an MVC component. It also supports server-rendered applications, where returning a String may mean “view name”.

@ResponseBody

Writes a method return value to the HTTP body through an HttpMessageConverter, for example as JSON.

@RestController

A composed annotation combining @Controller and @ResponseBody for every handler method.

@RequestMapping

Can be placed on a class to define a common base path and shared mapping rules.

@RestController
@RequestMapping(path = "/api/orders", produces = MediaType.APPLICATION_JSON_VALUE)
public class OrderController {
    // every handler writes its return value to the HTTP response
}

@RestController is normally the right choice for a JSON API. @Controller + @ResponseBody remains valid when you deliberately mix REST handlers and view rendering.

03

Routes and HTTP verbs

@RequestMapping is the general-purpose mapping annotation. @GetMapping, @PostMapping, @PutMapping, @PatchMapping, and @DeleteMapping are composed annotations that make the HTTP method explicit.

AnnotationTypical useExample
@GetMappingRead one or more resources.GET /api/orders/42
@PostMappingCreate a resource or trigger a non-idempotent operation.POST /api/orders
@PutMappingReplace resource state idempotently.PUT /api/orders/42
@PatchMappingPartially modify a resource.PATCH /api/orders/42
@DeleteMappingDelete a resource.DELETE /api/orders/42
@RequestMappingGeneral mapping or more specific conditions.method = RequestMethod.HEAD
@PostMapping(
    consumes = MediaType.APPLICATION_JSON_VALUE,
    produces = MediaType.APPLICATION_JSON_VALUE
)
public ResponseEntity<OrderResponse> create(...) { ... }

The important mapping attributes are path/value, method, params, headers, consumes, and produces. The latter four can select between handlers that otherwise share the same path.

@GetMapping(params = "status=PAID")
public List<OrderResponse> paidOrders() { ... }

@GetMapping(headers = "X-API-Version=2")
public List<OrderV2Response> listV2() { ... }

HTTP methods are not decoration. Choosing POST, PUT, or PATCH is part of the API contract and affects idempotency, retries, caching, proxies, and client expectations.

04

How data enters an endpoint

An HTTP request has several data locations: path, query string, headers, cookies, body, and multipart parts. Spring provides a distinct annotation for each source.

AnnotationReadsExample
@PathVariableVariable embedded in the path./orders/{id}
@RequestParamQuery parameter or form data.?page=0&size=20
@RequestHeaderHTTP header.X-Correlation-Id
@CookieValueA specific cookie.SESSION
@RequestBodyWhole body, deserialized.JSON → DTO
@RequestPartOne multipart part.JSON + file
@ModelAttributeBinding from parameters/form data into an object.Complex filters
@RequestAttributeAttribute previously placed on the request.Filter/interceptor data
@SessionAttributeExisting HTTP session attribute.Session state
@MatrixVariableMatrix parameter in a path segment./cars;color=red

@PathVariable

@GetMapping("/{id}")
public OrderResponse find(@PathVariable Long id) {
    return service.find(id);
}

@RequestParam

@GetMapping
public Page<OrderResponse> search(
    @RequestParam(defaultValue = "0") int page,
    @RequestParam(defaultValue = "20") int size,
    @RequestParam(required = false) OrderStatus status
) { ... }

required = false makes the parameter optional. defaultValue provides a value and effectively makes the parameter optional too.

@RequestHeader and @CookieValue

public OrderResponse find(
    @RequestHeader("X-Correlation-Id") String correlationId,
    @RequestHeader(value = "Accept-Language", required = false) String language,
    @CookieValue(value = "experiment", required = false) String experiment
) { ... }

@RequestBody

@PostMapping
public ResponseEntity<OrderResponse> create(
    @Valid @RequestBody CreateOrderRequest request
) { ... }

Spring delegates body reading to an HttpMessageConverter. With JSON, Jackson commonly turns the document into your DTO. @RequestBody is not “the JSON annotation”: it can work with other media types whenever a compatible converter exists.

Important detail: for traditional form data, prefer @RequestParam or @ModelAttribute. Spring's own documentation warns that form parameter access and subsequent @RequestBody reading can be unreliable with the Servlet API.

@RequestPart for multipart

@PostMapping(path = "/{id}/invoice", consumes = MediaType.MULTIPART_FORM_DATA_VALUE)
public void uploadInvoice(
    @PathVariable Long id,
    @Valid @RequestPart("metadata") InvoiceMetadata metadata,
    @RequestPart("file") MultipartFile file
) { ... }
05

Binding, dates, numbers and conversion rules

@ModelAttribute

Builds an object and binds request parameters to its properties. In REST APIs it is most useful for complex filters or form-based endpoints.

public record OrderFilter(OrderStatus status, LocalDate from, LocalDate to) {}

@GetMapping
public List<OrderResponse> search(@ModelAttribute OrderFilter filter) { ... }

@DateTimeFormat and @NumberFormat

public List<OrderResponse> search(
    @RequestParam
    @DateTimeFormat(iso = DateTimeFormat.ISO.DATE)
    LocalDate from
) { ... }

These annotations belong to Spring's conversion and formatting layer. They are useful for text arriving in paths, query parameters, or forms. Dates inside JSON are a different layer and are typically controlled by Jackson configuration such as @JsonFormat.

@InitBinder

@InitBinder customizes a controller's WebDataBinder: conversion, editors, and allowed fields. It is powerful, although reusable converters are often easier to maintain than scattered controller-specific binding logic.

06

@Valid, @Validated and Jakarta constraints

Binding transforms data. Validation decides whether that data is acceptable. Those are different concerns.

@Valid

jakarta.validation.Valid triggers cascaded validation. It is the usual choice on a request DTO.

public record CreateOrderRequest(
    @NotBlank String customerId,
    @NotEmpty @Valid List<OrderLineRequest> lines,
    @Email String contactEmail
) {}

public record OrderLineRequest(
    @NotBlank String sku,
    @Positive int quantity
) {}

@Validated

org.springframework.validation.annotation.Validated integrates Bean Validation with Spring and adds validation-group support, useful when the same model has different rules for different use cases.

Standard constraints worth recognizing

AnnotationChecks
@NotNull / @NullMust be non-null / null.
@NotEmptyNon-null and non-empty string, collection, map, or array.
@NotBlankNon-null text containing at least one non-whitespace character.
@Size(min,max)Size of text, collection, map, or array.
@Min / @MaxInteger numeric limits.
@DecimalMin / @DecimalMaxDecimal limits with inclusive/exclusive options.
@Positive / @PositiveOrZeroPositive / positive-or-zero values.
@Negative / @NegativeOrZeroNegative / negative-or-zero values.
@DigitsMaximum integer and fraction digits.
@PatternText matches a regular expression.
@EmailEmail syntax according to the validation provider.
@Past / @PastOrPresentPast / past-or-present date.
@Future / @FutureOrPresentFuture / future-or-present date.
@AssertTrue / @AssertFalseExpected boolean value.

@NotNull does not mean “non-empty text”. An empty string passes @NotNull. For required textual API input, @NotBlank often expresses the intent better.

@Constraint for custom validation

@Target({ ElementType.FIELD, ElementType.PARAMETER })
@Retention(RetentionPolicy.RUNTIME)
@Constraint(validatedBy = SkuValidator.class)
public @interface ValidSku {
    String message() default "invalid SKU";
    Class<?>[] groups() default {};
    Class<? extends Payload>[] payload() default {};
}

A custom constraint is useful when it expresses a reusable domain-format rule. If validation needs database access, permissions, or external state, it is usually application logic rather than a simple Bean Validation constraint.

07

Controlling the HTTP response

@ResponseStatus

Sets an HTTP status on a handler method or exception.

@PostMapping
@ResponseStatus(HttpStatus.CREATED)
public OrderResponse create(@Valid @RequestBody CreateOrderRequest request) {
    return service.create(request);
}

For dynamic responses —status, headers, or body varying by outcome— ResponseEntity<T> is usually more explicit.

ResponseEntity is not an annotation. It is a response type. Keep it mentally separate from @ResponseStatus: one builds a response at runtime; the other is declarative metadata.

08

Errors: @ExceptionHandler and Advice

@ExceptionHandler

Declares a method that translates one or more exceptions into an HTTP response. Inside a controller, it only affects that controller.

@ExceptionHandler(OrderNotFoundException.class)
public ResponseEntity<ProblemDetail> handleNotFound(OrderNotFoundException ex) {
    ProblemDetail problem = ProblemDetail.forStatusAndDetail(
        HttpStatus.NOT_FOUND, ex.getMessage());
    return ResponseEntity.status(HttpStatus.NOT_FOUND).body(problem);
}

@ControllerAdvice and @RestControllerAdvice

@ControllerAdvice applies methods such as @ExceptionHandler, @InitBinder, and @ModelAttribute across controllers. @RestControllerAdvice combines that with @ResponseBody, which makes it especially convenient for REST APIs.

@RestControllerAdvice
public class ApiExceptionHandler {
    @ExceptionHandler(OrderNotFoundException.class)
    ResponseEntity<ProblemDetail> notFound(OrderNotFoundException ex) {
        var problem = ProblemDetail.forStatusAndDetail(HttpStatus.NOT_FOUND, ex.getMessage());
        problem.setTitle("Order not found");
        return ResponseEntity.status(HttpStatus.NOT_FOUND).body(problem);
    }
}

@ResponseStatus on an exception

It is concise, but couples an exception to HTTP. In larger applications it is often more flexible to keep domain exceptions transport-agnostic and translate them in an advice.

09

@CrossOrigin and CORS

@CrossOrigin configures CORS at class or handler level.

@CrossOrigin(origins = "https://app.example.com")
@RestController
@RequestMapping("/api/orders")
public class OrderController { ... }

It works well for local rules, but if the entire API shares one CORS policy, global configuration is usually easier to maintain, especially when Spring Security is present.

CORS is not authentication. It is a browser-enforced cross-origin policy. It does not replace JWT, sessions, OAuth 2.0, or server-side authorization.

Jackson annotations that change your JSON contract

These are not Spring MVC annotations, but they are common on REST DTOs because Jackson usually serializes and deserializes JSON.

AnnotationEffect
@JsonPropertyRenames a JSON property or controls its access.
@JsonIgnoreExcludes a property.
@JsonIgnorePropertiesIgnores several properties or unknown fields.
@JsonIncludeControls inclusion of null, empty, or default values.
@JsonFormatControls date/time or number formatting.
@JsonCreatorMarks a constructor/factory for deserialization.
@JsonValueDefines an object's or enum's JSON representation.
@JsonViewDefines serialization views.
@JsonTypeInfo / @JsonSubTypesSupport polymorphic payloads.

Architecture decision: avoid exposing JPA entities directly as REST responses. Separate DTOs prevent persistence annotations, lazy loading, and bidirectional relationships from accidentally defining the public JSON contract.

11

Security annotations

HTTP authorization can be configured by routes in SecurityFilterChain or by methods. Spring Security provides several method-security annotation families.

@EnableMethodSecurity

@Configuration
@EnableMethodSecurity
public class SecurityConfig { ... }

It enables method-security infrastructure. Adding Spring Security's starter alone does not activate method-level authorization annotations.

@PreAuthorize and @PostAuthorize

@PreAuthorize("hasAuthority('orders:write')")
@PostMapping
public OrderResponse create(...) { ... }

@PostAuthorize("returnObject.customerId() == authentication.name")
@GetMapping("/{id}")
public OrderResponse find(@PathVariable Long id) { ... }

@PreAuthorize decides before invocation. @PostAuthorize decides afterwards and can inspect the returned object. In business APIs, protecting service methods as well as—or instead of—only controllers avoids making authorization dependent on a single entry point.

@PreFilter and @PostFilter

They filter input/output collections using authorization expressions. They are powerful but can hide data-access cost; for large collections, apply authorization in the query rather than loading data only to discard it afterwards.

@Secured and JSR-250

AnnotationNote
@SecuredLegacy Spring Security option; explicitly enabled.
@RolesAllowedJakarta/JSR-250 standard role annotation.
@PermitAllAllows access in the JSR-250 model.
@DenyAllDenies access to the method.

@AuthenticationPrincipal

@GetMapping("/me/orders")
public List<OrderResponse> mine(@AuthenticationPrincipal Jwt jwt) {
    return service.findByCustomer(jwt.getSubject());
}
12

OpenAPI / Swagger annotations

With springdoc-openapi, annotations under io.swagger.v3.oas.annotations enrich the generated API contract. They do not change how Spring executes a request; they change how the endpoint is described.

AnnotationDocuments
@TagGroups operations.
@OperationSummary, description, operationId, security, and more.
@ParameterPath/query/header/cookie parameter.
@ApiResponseOne possible HTTP response.
@ApiResponsesA set of responses.
@ContentMedia type and schema for request/response content.
@SchemaModels, properties, examples, formats, constraints.
@ArraySchemaArray/collection schemas.
@ExampleObjectExplicit payload examples.
@SecurityRequirementSecurity scheme required by an operation.
@HiddenHides an operation or schema from documentation.
@Operation(summary = "Create an order")
@ApiResponses({
    @ApiResponse(responseCode = "201", description = "Order created"),
    @ApiResponse(responseCode = "400", description = "Invalid request")
})
@PostMapping
public ResponseEntity<OrderResponse> create(...) { ... }

Watch the duplicate name: Spring has org.springframework.web.bind.annotation.RequestBody, while OpenAPI has io.swagger.v3.oas.annotations.parameters.RequestBody. They are different annotations. Check imports and use a fully qualified name when that improves clarity.

13

Less common annotations in a REST API

@SessionAttributes

Promotes model attributes into an HTTP session during an MVC flow. In a stateless REST API, its presence should make you revisit the design.

@ModelAttribute on methods

Can preload model attributes before handlers execute. Common in MVC with views, less so in REST controllers.

@CookieValue

Useful when a cookie genuinely belongs to the contract; uncommon in machine-to-machine APIs.

@MatrixVariable

Supported by Spring, although matrix parameters are uncommon in modern public APIs.

Spring supporting an annotation does not mean you need it. A maintainable API usually uses a small and consistent subset.

Complete example: a reasonable production controller

This example combines the pieces without turning the controller into an annotation catalogue:

@RestController
@RequestMapping(path = "/api/orders", produces = MediaType.APPLICATION_JSON_VALUE)
@Tag(name = "Orders")
public class OrderController {

    private final OrderService service;

    public OrderController(OrderService service) {
        this.service = service;
    }

    @Operation(summary = "Get an order")
    @GetMapping("/{id}")
    @PreAuthorize("hasAuthority('orders:read')")
    public OrderResponse find(
        @PathVariable @Positive Long id,
        @RequestHeader(value = "X-Correlation-Id", required = false)
        String correlationId
    ) {
        return service.find(id);
    }

    @GetMapping
    public Page<OrderResponse> search(
        @RequestParam(required = false) OrderStatus status,
        @RequestParam(defaultValue = "0") @PositiveOrZero int page,
        @RequestParam(defaultValue = "20") @Min(1) @Max(100) int size
    ) {
        return service.search(status, page, size);
    }

    @Operation(summary = "Create an order")
    @PostMapping(consumes = MediaType.APPLICATION_JSON_VALUE)
    @PreAuthorize("hasAuthority('orders:write')")
    public ResponseEntity<OrderResponse> create(
        @Valid @RequestBody CreateOrderRequest request
    ) {
        OrderResponse created = service.create(request);
        URI location = URI.create("/api/orders/" + created.id());
        return ResponseEntity.created(location).body(created);
    }

    @DeleteMapping("/{id}")
    @ResponseStatus(HttpStatus.NO_CONTENT)
    @PreAuthorize("hasAuthority('orders:write')")
    public void delete(@PathVariable Long id) {
        service.delete(id);
    }
}

Notice what is not in the controller: persistence, transactions, JPA entities, and business logic. A REST API may use many annotations, but the HTTP boundary should not absorb every layer's responsibilities.

15

Mistakes seen in real projects

JPA entities as DTOs

Mixes @Entity, relationships, and Jackson in one object, exposing internals, cycles, or lazy-loading behavior.

@RequestParam for everything

A complex creation command is usually more stable as a @RequestBody DTO than as twelve query parameters.

The wrong @NotNull

For required text, @NotBlank normally describes the intent more accurately.

@CrossOrigin("*") without a policy

It quickly fixes a browser symptom while hiding the need for deliberate CORS design.

Security only on controllers

If a service is called by jobs, listeners, or another interface, the authorization rule can be bypassed.

Swagger as a copy of code

Manually duplicating every inferred type and status creates documentation that ages badly.

17

The rule that saves you from memorizing 50 annotations

Think about the request journey: mapping → data extraction → conversion → validation → authorization → application logic → serialization → status/headers → documentation.

A useful REST annotation almost always participates in one of those steps. If you know which step you are working on, you can usually infer which annotation family you need.

It also helps to separate contract from infrastructure. @GetMapping, @RequestBody, and @ResponseStatus clearly describe the HTTP boundary. @Transactional, @Entity, and @Cacheable may exist in the same application, but they are not REST annotations: they belong to other responsibilities.
