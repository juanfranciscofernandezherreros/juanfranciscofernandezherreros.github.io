Essential Java and Spring annotations

The annotations you should recognize immediately in a modern Java project: from @Override to @Transactional, with examples, nuances, and common mistakes.

01

First: what an annotation really is

An annotation is metadata attached to code. It can be consumed by the compiler, build tools, frameworks through reflection, or annotation processors to validate code, generate code, or decide behavior.

@Override
public String toString() {
    return "Order";
}

An annotation is not a method call. By itself it does not “execute” anything. Its meaning depends on who interprets it: the compiler, Spring, Hibernate, JUnit, Jakarta Validation, and so on.

02

Core Java annotations

@Override

Checks that a method actually overrides a superclass or interface method.

@Deprecated

Marks an API that should not be used in new code and may be removed later.

@SuppressWarnings

Suppresses specific compiler warnings when you have a justified reason.

@FunctionalInterface

Declares that an interface must remain a valid single-abstract-method interface.

@FunctionalInterface
public interface PriceCalculator {
    BigDecimal calculate(Order order);
}

Interview nuance: @Override is more than documentation; it lets the compiler catch mistakes such as using the wrong method signature.

03

@Deprecated and @SuppressWarnings: use them intentionally

@Deprecated(since = "3.2", forRemoval = true)
public void oldCheckout() {
    // temporary compatibility
}

since documents when the API became deprecated and forRemoval = true communicates an actual intention to remove it.

@SuppressWarnings("unchecked")
List<Order> orders = (List<Order>) legacyApi.load();

Avoid adding @SuppressWarnings("all") to hide problems. Suppress only the warning you understand and at the smallest reasonable scope.

04

@SafeVarargs and generics

@SafeVarargs states that a method with generic varargs does not perform unsafe operations on those arguments.

@SafeVarargs
static <T> List<T> concat(List<T>... lists) {
    return Stream.of(lists)
        .flatMap(Collection::stream)
        .toList();
}

It is a promise from the programmer to the compiler. If the promise is false, you can hide heap-pollution problems.

05

How to create your own annotations

To understand frameworks such as Spring, you should know the meta-annotations that define how a custom annotation behaves.

AnnotationPurpose
@TargetDefines where it may be used: type, method, field, parameter, and so on.
@RetentionDefines how long it exists: SOURCE, CLASS, or RUNTIME.
@DocumentedMakes it appear in generated Javadoc.
@InheritedAllows a class annotation to be inherited under specific rules.
@RepeatableAllows the same annotation to be used more than once on an element.
 
@Target(ElementType.METHOD)
@Retention(RetentionPolicy.RUNTIME)
@Documented
public @interface Audited {
    String action();
}
@Audited(action = "CONFIRM_PAYMENT")
public void confirmPayment(Long paymentId) {
    // ...
}
06

Spring stereotypes

@Component

Generic component discovered through component scanning.

@Service

Semantic specialization for application or domain-service logic.

@Repository

Persistence component; it can participate in exception translation.

@Controller / @RestController

Spring MVC web boundary. @RestController combines controller behavior with @ResponseBody.

@RestController
@RequestMapping("/api/orders")
public class OrderController {
    private final OrderService service;

    public OrderController(OrderService service) {
        this.service = service;
    }

    @GetMapping("/{id}")
    public OrderResponse find(@PathVariable Long id) {
        return service.find(id);
    }
}

For a deeper comparison, read Spring stereotype annotations.

07

@Configuration and @Bean

@Configuration marks a configuration class. @Bean explicitly registers the object returned by a method in the container.

@Configuration
public class AppConfig {

    @Bean
    public ObjectMapper objectMapper() {
        return new ObjectMapper()
            .findAndRegisterModules();
    }
}

This is particularly useful when you cannot annotate the target class, for example a third-party library type.

08

@Autowired, @Qualifier and @Primary

With a single constructor, Spring can inject dependencies without @Autowired. That is usually the preferred option.

@Service
public class CheckoutService {
    private final PaymentGateway gateway;

    public CheckoutService(PaymentGateway gateway) {
        this.gateway = gateway;
    }
}

When several beans share the same type, @Qualifier selects a specific candidate and @Primary declares the preferred one.

public CheckoutService(
    @Qualifier("stripeGateway") PaymentGateway gateway
) {
    this.gateway = gateway;
}
09

@Value and @ConfigurationProperties

@Value is useful for small isolated values. For related configuration groups, @ConfigurationProperties usually scales better.

@ConfigurationProperties(prefix = "payments")
public record PaymentProperties(
    URI baseUrl,
    Duration timeout,
    int retries
) {}

This gives you clearer typing, grouping, and validation than scattering many @Value("${...}") expressions across the application.

10

@Transactional

@Transactional declares a transactional boundary that Spring normally applies through proxies.

@Service
public class TransferService {

    @Transactional
    public void transfer(Long from, Long to, BigDecimal amount) {
        debit(from, amount);
        credit(to, amount);
    }
}

Classic mistake: an internal call through this.transfer(...) can bypass the proxy and therefore the expected transactional interception.

11

Validation: @Valid, @Validated and constraints

public record CreateUserRequest(
    @NotBlank String name,
    @Email String email,
    @Min(18) int age
) {}
@PostMapping
public ResponseEntity<UserResponse> create(
    @Valid @RequestBody CreateUserRequest request
) {
    return ResponseEntity.ok(service.create(request));
}

@Valid triggers validation of the annotated object in the appropriate context. @Validated is Spring's integration that also supports validation groups and method-level validation.

12

Web annotations you should recognize

@RequestMapping

Defines base paths and common request conditions for a controller or method.

@GetMapping / @PostMapping

Specializations for concrete HTTP methods.

@PathVariable

Extracts values embedded in the URL path.

@RequestParam / @RequestBody

Reads query parameters or deserializes the HTTP request body.

13

JPA: the minimum annotations you will encounter

@Entity
@Table(name = "orders")
public class OrderEntity {

    @Id
    @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Long id;

    @Column(nullable = false)
    private BigDecimal total;
}

You should also recognize relationships such as @OneToMany, @ManyToOne, and @JoinColumn, but do not memorize JPA as a list: understand ownership, fetch type, cascades, and the impact of generated queries.

14

Testing: JUnit and Spring Test

@Test
void calculatesTotal() {
    assertEquals(new BigDecimal("20.00"), service.total(order));
}

@Test

Marks a JUnit 5 test method.

@BeforeEach

Prepares state before every test.

@SpringBootTest

Starts the full context when you need to verify wiring or integration.

@WebMvcTest / @DataJpaTest

Cheaper slices for focused web or persistence tests.

15

How to answer this in an interview

“In Java, an annotation is metadata that can be interpreted by the compiler, a tool, or a framework. In core Java, the ones I use most are @Override, @Deprecated, @SuppressWarnings, and @FunctionalInterface. To build custom annotations I need to understand @Target and @Retention. In Spring, I consider stereotypes such as @Service and @Repository, bean registration with @Configuration/@Bean, resolution with @Qualifier/@Primary, configuration with @ConfigurationProperties, transactions with @Transactional, validation with @Valid, and web annotations such as @GetMapping and @RequestBody to be foundational. The important part is not memorizing names but knowing who processes each annotation and what behavior it enables.”
