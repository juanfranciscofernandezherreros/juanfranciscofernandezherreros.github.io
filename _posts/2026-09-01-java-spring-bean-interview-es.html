¿Qué es un bean en Spring?

Un bean no es una clase especial: es un objeto que Spring crea, configura y gestiona dentro de su contenedor.

Nivel
Fundamentos
Tema
Spring Core
Objetivo
Entrevista técnica
01

La respuesta de 30 segundos

Un bean es una instancia de un objeto que Spring crea, configura y gestiona dentro de su contenedor IoC. La clase define cómo será el objeto; cuando Spring crea una instancia de esa clase y la registra en el ApplicationContext, esa instancia pasa a ser un bean. Spring también puede proporcionarle sus dependencias y gestionar su ciclo de vida.

La idea esencial es que bean no es un tipo de clase. Una clase Java normal puede dar lugar a un bean si registramos uno de sus objetos en el contenedor de Spring.

02

La clase y el bean no son lo mismo

Clase Java

Es la definición: declara los campos, constructores y métodos que tendrán sus objetos. Por sí sola no es un bean ni está gestionada por Spring.

Bean de Spring

Es un objeto concreto, es decir, una instancia que Spring ha registrado en su contenedor. Spring conoce ese objeto y puede inyectarlo donde se necesite.

Por ejemplo, EmailService es una clase. El objeto de EmailService que Spring crea y conserva en el contexto es el bean. Si creamos otro objeto con new EmailService(), ese objeto no es automáticamente un bean porque Spring no lo está gestionando.

No debe confundirse con JavaBean: JavaBean es una convención de clases con determinadas características, como propiedades accesibles mediante getters y setters. Un Spring Bean no necesita seguir esa convención.

03

Cómo se crea un Spring Bean

Spring puede descubrir nuestras clases mediante component scanning. @Component es la anotación general; @Service, @Repository y @Controller expresan responsabilidades más concretas.

@Service
public class EmailService {
    public void enviar(String mensaje) {
        System.out.println(mensaje);
    }
}

También podemos declarar un bean explícitamente con @Bean dentro de una clase @Configuration. Es especialmente útil para clases de librerías externas que no podemos anotar.

@Configuration
public class AppConfig {
    @Bean
    public ObjectMapper objectMapper() {
        return new ObjectMapper();
    }
}

Spring Boot no cambia la definición de bean. Facilita su registro mediante auto-configuración y component scanning, pero los beans siguen viviendo en el contenedor de Spring.

04

Inyección de dependencias

La inyección por constructor deja explícitas las dependencias, permite usar campos final y facilita las pruebas. Si hay un único constructor, Spring no necesita que añadamos @Autowired.

@RestController
public class UsuarioController {
    private final EmailService emailService;

    public UsuarioController(EmailService emailService) {
        this.emailService = emailService;
    }
}
Spring escanea configuración→Crea los beans→Resuelve dependencias→Inyecta objetos listos

Esto es inversión de control: nuestra clase no decide cómo construir todas sus colaboradoras. Cede esa responsabilidad al framework y se concentra en su comportamiento.

05

Ciclo de vida y scopes

De forma simplificada, Spring instancia el bean, inyecta sus dependencias, ejecuta callbacks como @PostConstruct, lo deja disponible y, al cerrar el contexto, puede ejecutar @PreDestroy.

  • singleton: una instancia por ApplicationContext; es el scope por defecto.
  • prototype: una instancia nueva cada vez que se solicita.
  • request: una instancia por petición HTTP.
  • session: una instancia por sesión HTTP.

Matiz de entrevista: el singleton de Spring significa una instancia por contenedor, no necesariamente una única instancia en toda la JVM.

06

Preguntas de seguimiento

¿@Bean o @Component?

@Component se coloca en la propia clase y se descubre automáticamente. @Bean se coloca en un método de configuración y nos permite controlar la construcción del objeto.

¿Qué ocurre si hay dos beans del mismo tipo?

La inyección se vuelve ambigua. Podemos elegir uno con @Qualifier o marcar el candidato habitual con @Primary.

¿Los beans son thread-safe?

No automáticamente. Como los servicios singleton pueden atender varios hilos, conviene que sean stateless o protejan correctamente cualquier estado mutable.

¿Puedo usar new?

Sí, pero ese objeto no será administrado por Spring. No recibirá automáticamente inyección, proxies, aspectos ni callbacks del ciclo de vida.

07

Respuesta completa para la entrevista

“Un bean en Spring es un objeto que el contenedor IoC crea, configura y gestiona. No es una clase especial: es una instancia de una clase Java registrada en el ApplicationContext. Spring puede resolver e inyectar sus dependencias y gestionar su ciclo de vida. Puedo registrarlo mediante component scanning, por ejemplo con @Service, o explícitamente con un método @Bean. Por defecto tiene scope singleton dentro del contexto.”

No hace falta recitarla literalmente. Mantén el orden objeto gestionado → registro en el contenedor → inyección → ciclo de vida y acompáñala con un ejemplo real de tu proyecto.
