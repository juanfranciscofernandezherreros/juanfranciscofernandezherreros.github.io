Java & Spring Interview Notes

What is a bean?

An explanation that connects Java, Spring Boot, and dependency injection without relying on an empty memorized definition.

Level
Foundations
Topic
Spring Core
Goal
Technical interview
01

The 30-second answer

A Spring Bean is an object created, configured, and managed by the Spring container. Instead of manually constructing its dependencies with new, we declare what it needs and Spring supplies those objects through dependency injection. By default, a bean has singleton scope within its ApplicationContext.

This answer contains the four ideas interviewers usually expect: it is an object, it belongs to the container, it receives dependencies, and it has a managed lifecycle.

02

JavaBean is not the same as Spring Bean

JavaBean

A class that follows Java conventions: private properties, getters and setters, and usually a no-argument constructor. It is a structural convention and does not require Spring.

Spring Bean

Any object registered in Spring's IoC container. It does not have to follow the JavaBean convention or expose getters, setters, or an empty constructor.

Common mistake: saying that a Spring Bean is merely a class with getters and setters. That describes a JavaBean and misses the essential role of the Spring container.

03

How a Spring Bean is created

Spring can discover our classes through component scanning. @Component is the general annotation, while @Service, @Repository, and @Controller communicate more specific responsibilities.

@Service
public class EmailService {
    public void send(String message) {
        System.out.println(message);
    }
}

We can also declare a bean explicitly with @Bean inside a @Configuration class. This is particularly useful for third-party classes that we cannot annotate.

@Configuration
public class AppConfig {
    @Bean
    public ObjectMapper objectMapper() {
        return new ObjectMapper();
    }
}

Spring Boot does not change the definition of a bean. It makes registration easier through auto-configuration and component scanning, but the beans still live in the Spring container.

04

Dependency injection

Constructor injection makes dependencies explicit, allows fields to be final, and simplifies testing. When there is a single constructor, Spring does not require us to add @Autowired.

@RestController
public class UserController {
    private final EmailService emailService;

    public UserController(EmailService emailService) {
        this.emailService = emailService;
    }
}
Spring scans configuration→Creates beans→Resolves dependencies→Injects ready objects

This is inversion of control: our class does not decide how to construct all its collaborators. It delegates that responsibility to the framework and focuses on its own behavior.

05

Lifecycle and scopes

In simplified terms, Spring instantiates the bean, injects its dependencies, runs callbacks such as @PostConstruct, makes it available, and may run @PreDestroy when the context closes.

  • singleton: one instance per ApplicationContext; this is the default scope.
  • prototype: a new instance every time it is requested.
  • request: one instance per HTTP request.
  • session: one instance per HTTP session.

Interview nuance: a Spring singleton means one instance per container, not necessarily one instance in the entire JVM.

06

Follow-up questions

@Bean or @Component?

@Component goes on the class and is discovered automatically. @Bean goes on a configuration method and gives us control over object construction.

What if two beans have the same type?

Injection becomes ambiguous. We can select one with @Qualifier or mark the usual candidate with @Primary.

Are beans thread-safe?

Not automatically. Because singleton services may serve multiple threads, they should normally be stateless or correctly protect mutable state.

Can I use new?

Yes, but that object will not be managed by Spring. It will not automatically receive injection, proxies, aspects, or lifecycle callbacks.

07

The complete interview answer

“A bean in Spring is an instance managed by the IoC container. Spring creates it, resolves and injects its dependencies, and manages its lifecycle. I can register it through component scanning, for example with @Service, or explicitly with a @Bean method. Its default scope is singleton within the context. It should not be confused with a JavaBean, which is simply a class that follows a set of conventions.”

You do not need to recite it word for word. Keep the sequence definition → creation → injection → lifecycle → difference from JavaBean, then support it with a real example from your project.
