Arduino from scratch · real experiment

My first Arduino traffic light

I started by blinking one LED and then built a two-light version with red and yellow. The current circuit now has the complete logic of a simple three-LED traffic light: green for 5 seconds, yellow for 2, and red for 5. That extra LED adds a third digital output and turns the exercise into a small timed state machine.

00

The real build I have right now

This article documents the circuit exactly as I have it wired, not an idealized version. I use three LEDs —red, yellow, and green— controlled by digital pins 8, 9, and 10. Each LED has its own resistor and each branch also returns to GND through its own wire.

So I am not using one shared negative rail on the breadboard. I have three separate return wires: one for red, one for yellow, and one for green. All three end at ground.

Important: if those three wires really terminate on GND pins of the same board, they are electrically part of the same ground node. That is not “wrong” in the sense that the circuit cannot work; it is simply redundant, less tidy, and less scalable than bringing one GND wire to the breadboard and distributing ground from there.

The board is powered and programmed over USB. The current behavior is: green for 5 seconds, yellow for 2 seconds, and red for 5 seconds. Then loop() starts again.

01

What I used

Arduino

An Arduino Uno-compatible board connected over USB. USB powers the board and lets Arduino IDE upload the program.

Breadboard

It lets us build the circuit without soldering. The holes are not individually isolated: they are internally connected in groups.

Three LEDs

Red, yellow, and green. LEDs are polarized components: anode and cathode are not interchangeable.

Three resistors

One per LED, typically 220 Ω or 330 Ω, to limit current and protect each LED and the microcontroller pin.

Jumper wires

Male-to-male jumpers connect the Arduino headers to the breadboard holes.

Arduino IDE

It compiles the sketch and uploads it to the microcontroller. After upload, the computer no longer decides when each LED changes: the board does.

02

Before wiring: understand the breadboard

This was the least obvious part at first. A breadboard looks like a huge matrix of independent holes, but underneath it has metal strips that connect specific groups of points.

In the central area, each group of five holes in the same row is electrically connected. The trench down the middle separates both sides: a row on the left is not automatically connected to the matching row on the right. The long rails usually marked + and - are commonly used to distribute power and ground, although this first build can work without using them if we wire the paths directly.

Practical rule: two leads inserted into holes that belong to the same conductive group are electrically connected. If both LED legs are accidentally placed in the same connected row, the circuit will not behave as expected.
03

LED polarity

An LED is a diode: it mainly allows current to flow in one direction. On a new LED, the long leg is usually the anode (+) and the short leg the cathode (-). The package also often has a flat side next to the cathode.

The current path in our circuit is:

digital pin → resistor → LED anode → LED cathode → GND

The resistor can go before or after the LED because both components are in series. What matters is that each branch has its own resistor.

04

Why we need the resistor

An LED does not behave like a bulb that we can connect directly to a source. Once it is forward biased, a small change in voltage can cause a large increase in current. The resistor limits that current to a sensible level.

A useful approximation comes from Ohm's law:

I = (Vpin - Vled) / R

Approximate example with a red LED:
Vpin ≈ 5 V
Vled ≈ 2 V
R = 220 Ω

I ≈ (5 - 2) / 220
I ≈ 0.0136 A = 13.6 mA

The exact values depend on the board and LED, but this explains why a resistor of a few hundred ohms is normal in this kind of exercise. Connecting the LED directly to the pin can demand too much current.

05

The real wiring: three signals and three GND returns

The current version uses three independent digital outputs: red on pin 8, yellow on pin 9, and green on pin 10. Each output drives its own LED + resistor branch.

The unusual part of my current build is the return path: instead of joining all three cathodes to one shared ground rail on the breadboard, each LED has its own wire returning to GND. So there are three physically separate return paths, even though electrically they end at the same ground reference inside the Arduino.

Is using three GND wires wrong?

Not necessarily. On an Arduino Uno, the points marked GND are electrically connected. If each of the three return wires really ends on GND, the LEDs still share the same reference even though you reached it with three separate wires.

What can be improved is the organization of the circuit. A cleaner approach would use one wire from Arduino GND to the breadboard's negative rail, then return all three LEDs to that rail. For this exercise the electrical result is effectively the same, but it uses fewer wires and makes later additions such as buttons, sensors, or more LEDs easier.

What we must not do: use a digital pin as if it were GND, remove the LED resistor, or connect a digital output directly to ground. Here we are talking about three ground return wires, not shorting pins 8, 9, or 10.
06

The program

The sketch is intentionally small:

const int red = 8;
const int yellow = 9;
const int green = 10;

void setup() {
  pinMode(red, OUTPUT);
  pinMode(yellow, OUTPUT);
  pinMode(green, OUTPUT);
}

void loop() {
  // 🟢 GREEN
  digitalWrite(red, LOW);
  digitalWrite(yellow, LOW);
  digitalWrite(green, HIGH);
  delay(5000);

  // 🟡 YELLOW
  digitalWrite(red, LOW);
  digitalWrite(yellow, HIGH);
  digitalWrite(green, LOW);
  delay(2000);

  // 🔴 RED
  digitalWrite(red, HIGH);
  digitalWrite(yellow, LOW);
  digitalWrite(green, LOW);
  delay(5000);
}

The three constants

red, yellow, and green give names to pins 8, 9, and 10. That makes the sketch express the circuit intent instead of forcing us to remember what each number means.

setup(): configure pin direction

setup() runs once after startup or reset. With pinMode(..., OUTPUT) we tell Arduino that these pins will drive electrical signals outward.

loop(): the sequence that never ends

loop() repeats continuously while the board has power. The sequence starts with green for 5 seconds, moves to yellow for 2 seconds, and then red for 5 seconds. After that it automatically returns to green.

07

What HIGH, LOW, and delay mean

digitalWrite(pin, HIGH) drives a digital output to the high logic state; LOW drives it low. In our build, the high state creates the electrical conditions that let current flow through that branch and turn the LED on. The low state removes that difference and the LED turns off.

delay(5000) holds a state for 5 seconds, while delay(2000) holds it for 2. In this sketch, timing is part of the logic: green and red last 5 seconds; yellow lasts 2.

Important idea: Arduino does not “know” what a traffic light is. It only executes instructions on three pins. The meaning of “green”, “yellow”, and “red” comes from the wiring, the state order, and the timing we define.

The three outputs are independent. The software is what guarantees that only one light is on in each phase. The complete cycle lasts 12 seconds: 5 + 2 + 5.

09

Mistakes this build helps you understand

LED reversed

If anode and cathode are swapped, the LED will normally not light. Flipping it around is one of the first checks.

Wrong breadboard row

A lead or jumper shifted by one hole can leave the circuit open because it no longer shares the expected internal connection.

Return to GND

Each LED needs a path back to ground. In my build that return uses three separate wires; it works because all of them end at GND, although one shared rail would be cleaner.

Code and pin do not match

If the wire is on pin 9 but the sketch writes to pin 8, Arduino controls a different output. Hardware and software must agree.

No resistor

Too much current can flow. Each LED needs a current-limiting resistor in series.

Compile vs upload

Compiling checks and builds the program; uploading actually transfers it to the microcontroller.

10

What we actually learned

The goal was not to build a real traffic light. It was to build a mental model. With three LEDs we use three independent digital outputs, turned HIGH and LOW into a visible physical effect, and saw that timing is part of system behavior.

We also separated the responsibilities of the hardware: Arduino chooses the logic state; the resistor limits current; the LED converts current into light; the breadboard provides the connections; and GND closes each branch. In my current build, that GND return is physically duplicated three times, one wire per LED.

The next interesting step is adding a pedestrian push button. At that point Arduino stops running only a timed sequence and starts reacting to an external input; after that we can replace delay() with millis() so the program can keep handling inputs while timing the lights.

Key idea: this small circuit already contains the basic structure of many embedded projects: inputs or program rules → logic → physical outputs. Understanding these three outputs is more valuable than memorizing a sketch, because the same idea comes back when LEDs are replaced by relays, motors, displays, or other actuators.
