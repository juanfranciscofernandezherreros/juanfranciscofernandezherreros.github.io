01

Qué hace el proyecto

Media Server construye y configura un ecosistema multimedia self-hosted completo. Una persona puede explorar y pedir una película o serie; la plataforma encuentra una versión adecuada, la descarga, le da un nombre coherente, añade subtítulos, puede reducir su tamaño y la deja disponible para verla desde el móvil, la televisión o un navegador.

El repositorio no crea un reproductor o un motor de descargas nuevo. Su valor está en la orquestación: empaqueta aplicaciones open source consolidadas con Docker Compose, prepara su almacenamiento, conecta sus APIs y aplica una configuración inicial útil. Así convierte una integración larga y propensa a errores en una instalación repetible.

02

De la petición a la reproducción

01 · PEDIR

Jellyseerr ofrece un catálogo amigable donde buscar un título y solicitarlo.

02 · ENCONTRAR

Sonarr o Radarr pide a Prowlarr que consulte las fuentes configuradas y elija un resultado.

03 · PREPARAR

qBittorrent o SABnzbd lo descarga; la automatización importa, renombra y ordena el archivo.

04 · VER

Bazarr añade subtítulos, Tdarr puede transcodificar y Jellyfin reproduce la biblioteca terminada.

Es una cadena dirigida por eventos, no una colección de paneles inconexos. Cada aplicación tiene una responsabilidad concreta y las carpetas compartidas y conexiones por API permiten que la salida de una etapa sea la entrada de la siguiente.

04

Qué automatiza la instalación

El script de configuración instala los prerrequisitos, crea los directorios de contenidos y configuración, levanta más de 25 contenedores, descubre las claves API generadas y enlaza los servicios. También establece credenciales, crea direcciones locales .media.local y ejecuta más de 90 comprobaciones sobre el sistema terminado.

La configuración se guarda en un fichero TOML legible. Incluye perfiles de calidad, idiomas de subtítulos, indexadores, VPN, Usenet y credenciales. El proceso es idempotente: se puede ejecutar de nuevo para hacer converger el sistema al mismo estado deseado; otros modos permiten validar, actualizar, crear copias de seguridad, restaurar o previsualizar cambios.

05

Para quién está pensado

Encaja con quien dispone de un servidor Linux doméstico o NAS, acepta gestionar el almacenamiento y el acceso de red, y prefiere una plataforma coherente frente a configurar cada aplicación a mano. Docker aísla los servicios, pero la máquina necesita suficiente disco y, si habrá transcodificación, capacidad adecuada de CPU o GPU.

El control implica responsabilidad. El self-hosting permite decidir sobre cuentas, archivos y conservación, pero obliga a mantener actualizaciones y copias de seguridad, usar fuentes legales y proteger el acceso remoto. Por defecto, los servicios permanecen en la red local; Tailscale es la vía opcional prevista para acceder desde fuera. La VPN para las descargas también es opcional y está desactivada inicialmente.
