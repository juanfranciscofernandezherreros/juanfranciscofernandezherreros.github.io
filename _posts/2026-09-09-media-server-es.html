Media Server con Jellyfin

Una arquitectura privada con Docker Compose para transformar una petición autorizada en contenido organizado y disponible en Jellyfin, sin exponer la administración a Internet.

01

El problema que resuelve

Un Media Server es una integración, no solo un reproductor. Solicitudes, búsqueda, descargas, rutas compartidas, subtítulos, reproducción y seguridad de red deben funcionar como una única cadena. Configurar cada aplicación de forma aislada suele acabar en imports rotos, puertos expuestos de más o descargas que no pasan por la VPN.

El repositorio ensambla aplicaciones open source consolidadas y define sus fronteras: Jellyfin comparte la red de Tailscale, Deluge comparte la de Gluetun y los paneles administrativos se limitan a localhost. Su valor está en que esa integración se puede repetir y comprobar.

02

De una petición a la reproducción

01 · PEDIR

Jellyseerr permite solicitar una película o serie.

02 · LOCALIZAR

Radarr o Sonarr consultan las fuentes administradas por Prowlarr.

03 · DESCARGAR

Deluge recibe el trabajo y sale por Gluetun y NordVPN.

04 · IMPORTAR Y VER

Radarr o Sonarr ordenan; Bazarr subtitula y Jellyfin reproduce.

El instalador prepara directorios, variables y contenedores; no debe inventar credenciales, fuentes permitidas, perfiles de calidad o idiomas. Esas decisiones se configuran en los paneles y siguen siendo del operador.

04

Fronteras de red

Los usuarios remotos autorizados llegan a Jellyfin por Tailscale. Deluge sale por Gluetun con las credenciales manuales OpenVPN de NordVPN. Jellyseerr, Bazarr, Sonarr, Radarr, Prowlarr y Deluge se publican en 127.0.0.1, por lo que no se exponen a la LAN por defecto.

La regla esencial es mantener el router cerrado. Sonarr y Radarr deben usar gluetun:8112, nunca deluge:58846, porque Deluge comparte el namespace de red de Gluetun.

05

Rutas compartidas

Todos los servicios multimedia montan la raíz del proyecto como /data; así descarga e import usan las mismas ubicaciones:

/data/downloads   # trabajo de Deluge
/data/movies      # biblioteca de Radarr
/data/tv          # biblioteca de Sonarr
/data/media       # espacio adicional opcional

Las bases de datos, preferencias, tokens y configuraciones viven bajo docker/. Ese directorio y .env no se guardan en Git y deben formar parte de las copias de seguridad.

06

Instalación, diagnóstico y observabilidad

El instalador de Windows comprueba Docker y Docker Compose, crea las carpetas necesarias, genera .env desde el ejemplo, detecta placeholders, valida Compose y puede arrancar el stack.

git clone https://github.com/juanfranciscofernandezherreros/media-server.git
cd media-server
powershell -ExecutionPolicy Bypass -File .\scripts\install.ps1

Sustituye NORDVPN_USER y NORDVPN_PASSWORD por credenciales manuales de NordVPN, no por las credenciales habituales de la cuenta. Después configura Deluge con /data/downloads, conecta Prowlarr a Radarr y Sonarr, define sus carpetas raíz, conecta Bazarr, crea las bibliotecas en Jellyfin y une Jellyseerr a Jellyfin, Radarr y Sonarr.

powershell -ExecutionPolicy Bypass -File .\scripts\check-stack.ps1
docker compose -f docker-compose.observability.yml up -d

El diagnóstico verifica Compose, contenedores, conectividad mediante Gluetun, Jellyfin por Tailscale y puertos peligrosos. La observabilidad se despliega aparte con Grafana, Prometheus, Loki, Alloy y cAdvisor; en Windows, Prometheus usa Windows Exporter a través de host.docker.internal:9182.

07

Límites y operación responsable

El proyecto no descarga ni distribuye contenido por sí mismo, no añade fuentes automáticamente y no elimina la responsabilidad legal del operador. Está pensado para acceso privado, cuentas individuales de Jellyfin y fuentes permitidas en la jurisdicción aplicable.

Docker Compose da repetibilidad, no inmunidad ante discos llenos, credenciales caducadas o contenedores detenidos. Comprueba el estado antes y después de actualizar, respalda configuración y bibliotecas, y no ejecutes docker compose down -v salvo que quieras borrar datos persistentes.
