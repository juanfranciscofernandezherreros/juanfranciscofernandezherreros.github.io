01

El problema que resuelve

Un Media Server no es solo instalar un reproductor. Solicitudes, búsqueda, descargas, rutas compartidas, subtítulos, reproducción, acceso remoto y seguridad de red deben funcionar como una sola cadena. Configurar cada aplicación por separado suele producir imports rotos, puertos expuestos de más o descargas que no pasan por la VPN.

Este proyecto no crea un reproductor ni un cliente de descargas nuevo. Reúne aplicaciones open source consolidadas y define sus fronteras: Jellyfin comparte la red de Tailscale, Deluge comparte la de Gluetun y los paneles administrativos se limitan a localhost. Su valor está en esa integración reproducible y en poder comprobarla.

02

De una petición a la reproducción

01 · PEDIR

Jellyseerr permite solicitar una película o una serie.

02 · LOCALIZAR

Radarr o Sonarr consultan las fuentes administradas por Prowlarr.

03 · DESCARGAR

Deluge recibe el trabajo y sale por Gluetun y NordVPN.

04 · IMPORTAR Y VER

Radarr o Sonarr ordenan; Bazarr subtitula y Jellyfin reproduce.

El instalador prepara la base técnica, pero no debe inventar credenciales, fuentes permitidas, perfiles de calidad o idiomas. Esas decisiones permanecen en los paneles de cada aplicación y son responsabilidad del operador.

04

Las fronteras de red son la arquitectura

Los usuarios remotos autorizados llegan a Jellyfin mediante Tailscale. Deluge sale a Internet por Gluetun, con las credenciales manuales de servicio OpenVPN de NordVPN. Los paneles de Jellyseerr, Bazarr, Sonarr, Radarr, Prowlarr y Deluge se publican en 127.0.0.1, para que no se expongan a la LAN por defecto.

La regla esencial es mantener el router cerrado. Tailscale evita tener que abrir puertos al exterior. Para integrar el cliente de descargas, Sonarr y Radarr deben usar gluetun:8112, nunca deluge:58846: Deluge comparte el namespace de red de Gluetun.

05

Una ruta de datos compartida

Los servicios multimedia montan la raíz del repositorio como /data. Así, la descarga y el import hablan de las mismas ubicaciones:

/data/downloads   # trabajo de Deluge
/data/movies      # biblioteca gestionada por Radarr
/data/tv          # biblioteca gestionada por Sonarr
/data/media       # espacio adicional opcional

Las bases de datos, preferencias, tokens y configuraciones viven bajo docker/. Ese directorio y .env no se guardan en Git: deben formar parte del plan de backup junto con las bibliotecas que se quieran conservar.

06

Instalación y configuración inicial

El instalador de Windows comprueba Docker y Docker Compose, crea las carpetas necesarias, genera .env desde el ejemplo cuando falta, detecta placeholders, valida Compose y puede arrancar el stack.

git clone https://github.com/juanfranciscofernandezherreros/media-server.git
cd media-server
powershell -ExecutionPolicy Bypass -File .\scripts\install.ps1

Antes de esperar conectividad VPN, sustituye NORDVPN_USER y NORDVPN_PASSWORD por las credenciales manuales de NordVPN; no son el correo ni la contraseña normal de la cuenta. Para la observabilidad, define además la contraseña de Grafana.

Después configura Deluge con /data/downloads; conecta Prowlarr a Radarr y Sonarr; usa /data/movies y /data/tv como carpetas raíz; conecta Bazarr; crea las bibliotecas en Jellyfin; y une Jellyseerr a Jellyfin, Radarr y Sonarr. Una prueba de conexión correcta en cada panel vale más que asumir que los contenedores ya integran todo al estar iniciados.

07

Verificación, diagnóstico y observabilidad

El script de diagnóstico comprueba Docker, la sintaxis de Compose, el estado de los contenedores, la conectividad de Sonarr y Radarr con Deluge mediante Gluetun, la respuesta de Jellyfin por el namespace de Tailscale y exposiciones administrativas peligrosas.

powershell -ExecutionPolicy Bypass -File .\scripts\check-stack.ps1
docker compose ps
docker compose logs --tail=100 gluetun

Para validar la VPN, compara la IP pública del host con la obtenida desde Gluetun; deberían diferir salvo que el host también use VPN. El stack de observabilidad se arranca aparte:

docker compose -f docker-compose.observability.yml up -d

Grafana, Prometheus, Loki, Alloy y cAdvisor permanecen ligados a localhost. En Windows, Prometheus consulta Windows Exporter mediante host.docker.internal:9182. Separar este stack evita que un fallo de métricas interrumpa la reproducción, pero no reemplaza un backup ni revisar la salud de la VPN.

08

Límites y operación responsable

El proyecto no descarga ni distribuye contenido por sí mismo, no añade fuentes automáticamente y no elimina la responsabilidad legal del operador. Está pensado para acceso privado, cuentas individuales de Jellyfin y fuentes permitidas en la jurisdicción aplicable.

Docker Compose aporta repetibilidad, no inmunidad frente a discos llenos, credenciales caducadas, cambios de proveedor VPN o contenedores detenidos. Comprueba el estado antes y después de actualizar, respalda configuraciones y bibliotecas, y no ejecutes docker compose down -v salvo que quieras borrar datos persistentes.

01

Qué hace el proyecto

Media Server construye y configura un ecosistema multimedia self-hosted completo. Una persona puede explorar y pedir una película o serie; la plataforma encuentra una versión adecuada, la descarga, le da un nombre coherente, añade subtítulos, puede reducir su tamaño y la deja disponible para verla desde el móvil, la televisión o un navegador.

El repositorio no crea un reproductor o un motor de descargas nuevo. Su valor está en la orquestación: empaqueta aplicaciones open source consolidadas con Docker Compose, prepara su almacenamiento, conecta sus APIs y aplica una configuración inicial útil. Así convierte una integración larga y propensa a errores en una instalación repetible.

02

De la petición a la reproducción

01 · PEDIR

Jellyseerr ofrece un catálogo amigable donde buscar un título y solicitarlo.

02 · ENCONTRAR

Sonarr o Radarr pide a Prowlarr que consulte las fuentes configuradas y elija un resultado.

03 · PREPARAR

qBittorrent o SABnzbd lo descarga; la automatización importa, renombra y ordena el archivo.

04 · VER

Bazarr añade subtítulos, Tdarr puede transcodificar y Jellyfin reproduce la biblioteca terminada.

Es una cadena dirigida por eventos, no una colección de paneles inconexos. Cada aplicación tiene una responsabilidad concreta y las carpetas compartidas y conexiones por API permiten que la salida de una etapa sea la entrada de la siguiente.

04

Qué automatiza la instalación

El script de configuración instala los prerrequisitos, crea los directorios de contenidos y configuración, levanta más de 25 contenedores, descubre las claves API generadas y enlaza los servicios. También establece credenciales, crea direcciones locales .media.local y ejecuta más de 90 comprobaciones sobre el sistema terminado.

La configuración se guarda en un fichero TOML legible. Incluye perfiles de calidad, idiomas de subtítulos, indexadores, VPN, Usenet y credenciales. El proceso es idempotente: se puede ejecutar de nuevo para hacer converger el sistema al mismo estado deseado; otros modos permiten validar, actualizar, crear copias de seguridad, restaurar o previsualizar cambios.

05

Para quién está pensado

Encaja con quien dispone de un servidor Linux doméstico o NAS, acepta gestionar el almacenamiento y el acceso de red, y prefiere una plataforma coherente frente a configurar cada aplicación a mano. Docker aísla los servicios, pero la máquina necesita suficiente disco y, si habrá transcodificación, capacidad adecuada de CPU o GPU.

El control implica responsabilidad. El self-hosting permite decidir sobre cuentas, archivos y conservación, pero obliga a mantener actualizaciones y copias de seguridad, usar fuentes legales y proteger el acceso remoto. Por defecto, los servicios permanecen en la red local; Tailscale es la vía opcional prevista para acceder desde fuera. La VPN para las descargas también es opcional y está desactivada inicialmente.
