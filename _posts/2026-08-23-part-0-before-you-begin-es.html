Argo Real World Microservices — Parte 0 de la serie

Antes de empezar

La Parte 1 recorre cómo desplegar un microservicio con ArgoCD, y asume que ocho cosas ya están instaladas en tu máquina. Esta es la parte donde de verdad las instalas — qué es cada una, el comando exacto, y cómo comprobar que funcionó.

00

Lo que tendrás al terminar

Una máquina capaz de compilar una app Java pequeña, empaquetarla como contenedor, levantar un clúster de Kubernetes local, y hablar con él — todo lo que necesita Parte 1 — Hello World con ArgoCD. Unos 20-30 minutos, la mayoría descargas.

¿Primera vez con alguna de estas herramientas?

Esta página es solo instalación — no explica qué es realmente un contenedor, un clúster de Kubernetes, o GitOps. Lee primero la Introducción para la teoría, sin ningún comando de por medio.

01

Las herramientas, y para qué sirve cada una

Ocho cosas, cuatro trabajos. Nada de esto es específico de ArgoCD salvo la última.

Git
Descarga los dos repos que usa la Parte 1 (hello-world-argocd, gitops-config) y te deja subirles cambios.
Una cuenta de GitHub
Donde viven esos dos repos. Gratis, date de alta en github.com/signup si todavía no tienes — nada más de esta lista necesita cuenta.
Docker Desktop
Ejecuta contenedores, y por debajo, todo el clúster de Kubernetes local — kind es solo una capa fina encima.
kind
Crea y borra el propio clúster de Kubernetes local, dentro de Docker.
kubectl
Habla con el clúster que creó kind — todos los comandos que empiezan por kubectl en la Parte 1 necesitan esto.
Java 21 + Maven
Compila el microservicio de ejemplo. Específico de que este ejemplo en concreto sea una app Spring Boot — un ejemplo distinto en la Parte 1 necesitaría otro lenguaje en su lugar.
CLI de ArgoCD
El comando argocd — deja disparar una sincronización desde la terminal en vez de la interfaz web. Todo lo que hace también se puede hacer haciendo clic en el navegador, así que esta es la más opcional de las ocho.
02

Instálalas (Windows)

Un comando por herramienta, con winget (viene integrado en Windows 10/11 — no hace falta instalarlo aparte). Ejecuta esto en PowerShell.

Git

winget install Git.Git

Docker Desktop

winget install Docker.DockerDesktop

Pide iniciar sesión la primera vez que lo abres (gratis para uso personal), y reiniciar en algunas máquinas. Arráncalo ahora — el resto de esta página asume que está corriendo.

kind

winget install Kubernetes.kind

kubectl

Ya viene incluido con Docker Desktop en Windows — nada que instalar aparte. Si alguna vez falta: winget install Kubernetes.kubectl.

Java 21

winget install EclipseAdoptium.Temurin.21.JDK

Maven

winget install Apache.Maven

CLI de ArgoCD

winget install argoproj.argocd

Después de instalar, cierra y vuelve a abrir tu terminal — winget actualiza el PATH, pero solo las ventanas de terminal nuevas se enteran.

03

Verifica que todo funciona

Un comando por herramienta. Todos deberían imprimir un número de versión — si no sale versión, no es que la herramienta esté rota, es que el PATH no la ve.

git --version
docker --version
kind version
kubectl version --client
java -version
mvn -version
argocd version --client

Una comprobación extra, solo para Docker

docker --version solo demuestra que el CLI está instalado, no que el motor esté corriendo. Ejecuta también docker ps — una tabla vacía (CONTAINER ID IMAGE COMMAND ... sin filas) significa que está arriba. Un error de conexión significa que Docker Desktop todavía está arrancando, o hay que abrirlo.
