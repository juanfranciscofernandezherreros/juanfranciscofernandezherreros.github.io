01

Primero: qué es realmente una anotación

Una anotación es metadato asociado al código. Puede ser utilizada por el compilador, por herramientas de build, por frameworks mediante reflexión o por procesadores de anotaciones para cambiar validaciones, generar código o decidir comportamiento.

@Override
public String toString() {
    return "Order";
}

La anotación no es una llamada a método. Por sí sola no “ejecuta” nada. Su significado depende de quién la interprete: el compilador, Spring, Hibernate, JUnit, Jakarta Validation, etc.

02

Las anotaciones básicas de Java

@Override

Verifica que un método realmente sobrescribe otro método de una superclase o interfaz.

@Deprecated

Marca una API que no debería usarse en código nuevo y que puede desaparecer en el futuro.

@SuppressWarnings

Silencia warnings concretos del compilador cuando existe una razón justificada.

@FunctionalInterface

Declara que una interfaz debe tener exactamente un método abstracto funcional.

@FunctionalInterface
public interface PriceCalculator {
    BigDecimal calculate(Order order);
}

En entrevista: @Override es más que documentación: permite que el compilador detecte errores como escribir mal la firma del método.

03

@Deprecated y @SuppressWarnings: úsalas con intención

@Deprecated(since = "3.2", forRemoval = true)
public void oldCheckout() {
    // compatibilidad temporal
}

since documenta desde qué versión está obsoleta la API y forRemoval = true comunica que existe intención real de eliminarla.

@SuppressWarnings("unchecked")
List<Order> orders = (List<Order>) legacyApi.load();

Evita poner @SuppressWarnings("all") para esconder problemas. Silencia únicamente el warning que entiendes y en el alcance más pequeño posible.

04

@SafeVarargs y genéricos

@SafeVarargs indica que un método con varargs genéricos no realiza operaciones inseguras sobre esos argumentos.

@SafeVarargs
static <T> List<T> concat(List<T>... lists) {
    return Stream.of(lists)
        .flatMap(Collection::stream)
        .toList();
}

Es una promesa del programador al compilador. Si la promesa es falsa, puedes ocultar problemas de heap pollution.

05

Cómo crear tus propias anotaciones

Para entender frameworks como Spring, conviene conocer las meta-anotaciones que definen cómo funciona una anotación personalizada.

AnotaciónPara qué sirve
@TargetDefine dónde puede usarse: clase, método, campo, parámetro, etc.
@RetentionDefine cuánto tiempo existe: SOURCE, CLASS o RUNTIME.
@DocumentedHace que aparezca en el Javadoc.
@InheritedPermite que una anotación de clase se herede en determinadas condiciones.
@RepeatablePermite repetir la misma anotación sobre un elemento.
 
@Target(ElementType.METHOD)
@Retention(RetentionPolicy.RUNTIME)
@Documented
public @interface Audited {
    String action();
}
@Audited(action = "CONFIRM_PAYMENT")
public void confirmPayment(Long paymentId) {
    // ...
}
06

Estereotipos de Spring

@Component

Componente genérico descubierto mediante component scanning.

@Service

Especialización semántica para lógica de aplicación o dominio.

@Repository

Componente de persistencia; puede participar en traducción de excepciones.

@Controller / @RestController

Límite web MVC. @RestController combina controlador y @ResponseBody.

@RestController
@RequestMapping("/api/orders")
public class OrderController {
    private final OrderService service;

    public OrderController(OrderService service) {
        this.service = service;
    }

    @GetMapping("/{id}")
    public OrderResponse find(@PathVariable Long id) {
        return service.find(id);
    }
}

Para profundizar en las diferencias, consulta Anotaciones estereotipo en Spring.

07

@Configuration y @Bean

@Configuration marca una clase de configuración. @Bean registra explícitamente el objeto devuelto por un método en el contenedor.

@Configuration
public class AppConfig {

    @Bean
    public ObjectMapper objectMapper() {
        return new ObjectMapper()
            .findAndRegisterModules();
    }
}

Es especialmente útil cuando no puedes anotar la clase objetivo, por ejemplo una clase de una librería externa.

08

@Autowired, @Qualifier y @Primary

Con un único constructor, Spring puede inyectar las dependencias sin necesidad de @Autowired. Esa suele ser la opción preferida.

@Service
public class CheckoutService {
    private final PaymentGateway gateway;

    public CheckoutService(PaymentGateway gateway) {
        this.gateway = gateway;
    }
}

Cuando existen varios beans del mismo tipo, @Qualifier permite seleccionar uno concreto y @Primary establece el candidato preferido.

public CheckoutService(
    @Qualifier("stripeGateway") PaymentGateway gateway
) {
    this.gateway = gateway;
}
09

@Value y @ConfigurationProperties

@Value es útil para valores pequeños o aislados. Para bloques de configuración relacionados, @ConfigurationProperties suele escalar mejor.

@ConfigurationProperties(prefix = "payments")
public record PaymentProperties(
    URI baseUrl,
    Duration timeout,
    int retries
) {}

Esto ofrece tipado, agrupación y validación más claras que repartir muchos @Value("${...}") por la aplicación.

10

@Transactional

@Transactional declara una frontera transaccional que Spring aplica normalmente mediante proxies.

@Service
public class TransferService {

    @Transactional
    public void transfer(Long from, Long to, BigDecimal amount) {
        debit(from, amount);
        credit(to, amount);
    }
}

Error clásico: una llamada interna con this.transfer(...) puede saltarse el proxy y, por tanto, la interceptación transaccional esperada.

11

Validación: @Valid, @Validated y constraints

public record CreateUserRequest(
    @NotBlank String name,
    @Email String email,
    @Min(18) int age
) {}
@PostMapping
public ResponseEntity<UserResponse> create(
    @Valid @RequestBody CreateUserRequest request
) {
    return ResponseEntity.ok(service.create(request));
}

@Valid dispara validación en objetos anidados según el contexto. @Validated es una integración de Spring que además permite trabajar con validation groups y validación a nivel de método.

12

Anotaciones web que debes reconocer

@RequestMapping

Define rutas base y condiciones comunes para un controlador o método.

@GetMapping / @PostMapping

Especializaciones para métodos HTTP concretos.

@PathVariable

Extrae valores incluidos en la ruta.

@RequestParam / @RequestBody

Lee query parameters o deserializa el cuerpo HTTP.

13

JPA: las anotaciones mínimas que encontrarás

@Entity
@Table(name = "orders")
public class OrderEntity {

    @Id
    @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Long id;

    @Column(nullable = false)
    private BigDecimal total;
}

También debes reconocer relaciones como @OneToMany, @ManyToOne y @JoinColumn, pero evita memorizar JPA como una lista: entiende ownership, fetch type, cascades y el impacto de las consultas generadas.

14

Testing: JUnit y Spring Test

@Test
void calculatesTotal() {
    assertEquals(new BigDecimal("20.00"), service.total(order));
}

@Test

Marca un método de prueba en JUnit 5.

@BeforeEach

Prepara estado antes de cada test.

@SpringBootTest

Levanta el contexto completo cuando necesitas comprobar wiring o integración.

@WebMvcTest / @DataJpaTest

Slices más baratos para probar web o persistencia de forma enfocada.

15

Cómo responderlo en una entrevista

“En Java una anotación es metadato que puede interpretar el compilador, una herramienta o un framework. En Java estándar las más comunes son @Override, @Deprecated, @SuppressWarnings y @FunctionalInterface. Para crear anotaciones propias necesito entender @Target y @Retention. En Spring, las que considero básicas son los estereotipos como @Service y @Repository, registro con @Configuration/@Bean, resolución con @Qualifier/@Primary, configuración con @ConfigurationProperties, transacciones con @Transactional, validación con @Valid y las anotaciones web como @GetMapping y @RequestBody. Lo importante no es memorizar nombres sino saber quién procesa cada anotación y qué comportamiento activa.”
