01

The problem it solves

A Media Server is an integration, not only a player. Requests, search, downloading, shared paths, subtitles, playback, remote access and network safety need to work as one chain. Configuring every application in isolation commonly leads to broken imports, excessive public ports, or downloads that bypass the VPN.

This project does not create a player or a download client. It assembles established open-source applications and defines their boundaries: Jellyfin shares Tailscale's network, Deluge shares Gluetun's network, and administrative panels stay on localhost. Its value is that reproducible, verifiable integration.

02

From request to playback

01 · REQUEST

Jellyseerr lets someone request a film or series.

02 · FIND

Radarr or Sonarr query sources managed by Prowlarr.

03 · DOWNLOAD

Deluge receives the work and exits through Gluetun and NordVPN.

04 · IMPORT AND WATCH

Radarr or Sonarr organise it; Bazarr subtitles it and Jellyfin plays it.

The installer prepares the technical foundation, but it must not invent credentials, permitted sources, quality profiles or subtitle languages. Those choices remain in each application's UI and belong to the operator.

04

Network boundaries are the architecture

Authorised remote users reach Jellyfin through Tailscale. Deluge reaches the internet through Gluetun, using NordVPN manual OpenVPN service credentials. Jellyseerr, Bazarr, Sonarr, Radarr, Prowlarr and Deluge panels bind to 127.0.0.1, so they are not exposed to the LAN by default.

The essential rule is to keep the router closed. Tailscale removes the need to expose ports publicly. To integrate the download client, Sonarr and Radarr must use gluetun:8112, never deluge:58846: Deluge shares Gluetun's network namespace.

05

One shared data layout

Media services mount the repository root as /data. This means download and import use exactly the same locations:

/data/downloads   # Deluge work area
/data/movies      # Radarr-managed library
/data/tv          # Sonarr-managed library
/data/media       # optional extra space

Databases, preferences, tokens and configuration live under docker/. That directory and .env stay out of Git; they belong in the backup plan together with the libraries worth retaining.

06

Installation and initial setup

The Windows installer checks Docker and Docker Compose, creates required directories, creates .env from the example when absent, detects placeholders, validates Compose and can start the stack.

git clone https://github.com/juanfranciscofernandezherreros/media-server.git
cd media-server
powershell -ExecutionPolicy Bypass -File .\scripts\install.ps1

Before expecting VPN connectivity, replace NORDVPN_USER and NORDVPN_PASSWORD with NordVPN manual service credentials; they are not the normal account email and password. The observability stack also requires a Grafana password.

Then configure Deluge with /data/downloads; connect Prowlarr to Radarr and Sonarr; use /data/movies and /data/tv as root folders; connect Bazarr; create libraries in Jellyfin; and connect Jellyseerr to Jellyfin, Radarr and Sonarr. A successful connection test in each UI is stronger evidence than merely seeing containers running.

07

Verification, diagnostics and observability

The diagnostic script checks Docker, Compose syntax, container state, Sonarr and Radarr connectivity to Deluge through Gluetun, Jellyfin's response through the Tailscale namespace, and dangerous administrative port exposure.

powershell -ExecutionPolicy Bypass -File .\scripts\check-stack.ps1
docker compose ps
docker compose logs --tail=100 gluetun

To validate the VPN, compare the host public IP with Gluetun's public IP; they should differ unless the host also uses a VPN. Observability starts separately:

docker compose -f docker-compose.observability.yml up -d

Grafana, Prometheus, Loki, Alloy and cAdvisor remain localhost-bound. On Windows, Prometheus queries Windows Exporter through host.docker.internal:9182. Keeping monitoring separate prevents a metrics failure from interrupting playback, but it does not replace backups or reviewing VPN health.

08

Limits and responsible operation

The project does not download or distribute content by itself, does not add sources automatically, and does not remove the operator's legal responsibility. It is designed for private access, individual Jellyfin accounts and sources permitted in the relevant jurisdiction.

Docker Compose provides repeatability, not immunity to full disks, expired credentials, VPN-provider changes or stopped containers. Check state before and after updates, back up configuration and libraries, and never run docker compose down -v unless persistent data are meant to be deleted.

01

What the project does

Media Server builds and configures a complete self-hosted media ecosystem. A person can browse and request a film or series; the platform finds a suitable release, downloads it, gives it a consistent name, adds subtitles, optionally reduces its size and makes it available to stream from phones, televisions or a browser.

The repository is not a new video player or download engine. Its value is orchestration: it packages proven open-source applications with Docker Compose, creates their storage, connects their APIs and applies useful defaults. This turns what would otherwise be a long, error-prone integration job into a repeatable installation.

02

From request to playback

01 · REQUEST

Jellyseerr provides a friendly catalogue where users search for a title and ask for it.

02 · FIND

Sonarr or Radarr asks Prowlarr to search the configured sources and choose a matching release.

03 · PREPARE

qBittorrent or SABnzbd downloads it; the automation imports, renames and organizes the result.

04 · WATCH

Bazarr adds subtitles, Tdarr can transcode, and Jellyfin streams the finished library.

This is an event-driven chain rather than a pile of unrelated dashboards. Each application has a narrow responsibility, while shared folders and API connections allow the result of one stage to become the input of the next.

04

What installation automates

The setup script installs prerequisites, creates the media and configuration directories, launches more than 25 containers, discovers generated API keys and wires the services together. It also sets credentials, creates local .media.local addresses and runs over 90 checks against the finished system.

Configuration lives in a readable TOML file. It covers quality profiles, subtitle languages, indexers, VPN, Usenet and credentials. Setup is designed to be idempotent, so it can be run again to converge on the same desired state; dedicated modes validate, update, back up, restore or preview changes.

05

Who it is for

This project fits someone who has a Linux home server or NAS, is comfortable owning storage and network access, and wants one coherent platform instead of configuring every application manually. Docker isolates the services, but the machine still needs enough disk space and—if transcoding is expected—suitable CPU or GPU capacity.

Ownership matters. Self-hosting gives the operator control over accounts, files and retention, but also responsibility for updates, backups, lawful sources and safe remote access. The project keeps the services on the local network by default; Tailscale is the intended optional route for remote access. A VPN for download traffic is optional and disabled by default.
